# Local Chess Analyzer v2 Rewrite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v1 backend and frontend with a tested, modular FastAPI + Svelte 5 app that syncs games from chess.com and Lichess for multiple accounts, analyses them with Stockfish using chess.com-standard move classifications in a background queue, and presents a dark-first Game Review and dashboard.

**Architecture:** Single FastAPI process with an in-process two-lane job runner (analysis, sync), python-chess async UCI engine session, SQLite via SQLAlchemy 2.0 async, SSE for progress. Pure `domain/` package (no I/O) holds win-probability, SEE/sacrifice, classification, accuracy, openings, PGN helpers. Svelte 5 (runes) + TypeScript SPA built to static files and served by FastAPI at `/`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.0 (aiosqlite), python-chess, httpx, pydantic v2, uv, ruff, pytest + pytest-asyncio; Svelte 5, TypeScript, Vite 7, chessground, chess.js, vitest, svelte-check.

**Spec:** `docs/superpowers/specs/2026-09-15-v2-rewrite-design.md`

## Global Constraints

- Backend package is `lca`, run from `backend/`: `uv run uvicorn lca.main:app --port 42069`.
- Python ≥ 3.12. Node 22. SQLite DB file is `data/lca.db` (never touch `games.db`).
- `domain/` modules import nothing from `db/`, `services/`, `api/`, and never start processes.
- API responses use pydantic models from `lca/api/schemas.py`; errors are `{"error": {"code", "message"}}`.
- Classification labels (exact strings): `book, forced, brilliant, great, best, miss, excellent, good, inaccuracy, mistake, blunder`.
- time_class values: `bullet, blitz, rapid, classical, daily`. platform values: `chesscom, lichess`.
- Win% formula: `50 + 50 * (2 / (1 + exp(-0.00368208 * cp)) - 1)`; thresholds Δ ≤ 2/5/10/20.
- Frontend: no router/chart/CSS-framework dependencies; runtime deps are `chessground` and `chess.js` only; no `alert()`/`confirm()`.
- Every task ends with green tests and a commit. Commit messages end with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Before writing any chart component (Task 21) load the `dataviz` skill; before writing page UI (Tasks 16–22) the design tokens in `styles/tokens.css` are the only source of colour/spacing.

- [ ] **Step 1: Tests (FENs):**
  - Hanging queen: `4k3/8/8/3q4/8/8/8/4K2R w - - 0 1`? (use a rook that can take an undefended queen) → `see(board, d5)` for `8/8/8/3q4/8/8/8/3RK2k w - - 0 1` is 9.
  - Defended pawn attacked by rook: `see == 0` (rook would lose 5 for 1).
  - Greek gift `r1bq1rk1/ppp2ppp/2n1pn2/3p4/1bPP4/2NBPN2/PP3PPP/R2QK2R w KQ - 0 1`… use a clean constructed position: white bishop d3, black king g8, pawn h7 defended only by king: `is_piece_sacrifice(board, Move d3h7)` is True.
  - Exchange sac `Rxc3` recaptured by pawn → True. `Qxd8` with `Rxd8` recapture → False. Pawn push that hangs a pawn → False. Piece already hanging before the move and left hanging → False.
  - `is_simple_recapture`: after `...exd5`, `Nxd5` → True; unrelated capture → False.
- [ ] **Step 2:** fail. **Step 3: Implement** `see` recursively: `captures = [m for m in board.generate_legal_captures(to_mask=BB_SQUARES[square])]`; if none → 0; choose least valuable attacker; `nb = board.copy(stack=False); nb.push(m)`; `return max(0, PIECE_VALUES[captured] - see(nb, square))` where captured is the piece on `square` before the capture (promotion capture value = queen 9 − pawn 1 adjustments ignored). `is_piece_sacrifice` per spec §5.4.1 (use `before.copy(); push(Move.null())` for "already en prise" check unless `before.is_check()`). **Step 4:** pass. **Step 5:** commit `feat(domain): static exchange evaluation and sacrifice detection`.
